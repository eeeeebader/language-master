## Review

**Strengths.** The learning loop is coherent: a word met anywhere (lecture, story, dictionary)
lands in the same list model, the same drawer and the same scheduler. Everything is offline-first
with a real sync log design (append-only review events with `supersedes`). Content is data
(Zod-validated lecture and story documents), so the admin console and the audio build read the
same source. The audio story is finished end to end: pack, on-demand, story clips, mute switch.
CI is green on `main` (lint, typecheck, unit tests, builds, Playwright smoke, NLP tests, compose
checks) and release images are published on every merge.

**Debts to pay, roughly in order.**

1. **Sync has never run.** Everything downstream (profiles, friends, multi-device) depends on it.
2. **Dictionary glosses.** Wiktionary sense order is unreliable; `refine-pack` fixes the curated
   ~260 words. The real fix is gloss ranking in `build-pack` (WikDict `importance`, part-of-speech
   consistency) and needs the sources on a build machine.
3. **Admin content drift.** Seed the admin's lecture drafts from the shipped content after the
   first deploy (`pnpm --filter @lm/api seed-lectures -- --email <admin> --publish`).
4. **Packs on iOS.** 21 MB dictionary + 37 MB audio in IndexedDB; Safari may evict. Capacitor
   builds should use the filesystem plugin (`packFiles` and `audioClips` are the only touch points).
5. **Test coverage** is strong on algorithms (srs, pipeline, quota) and thin on integration (HTTP
   routes, audio install state machine, admin). No coverage reporter yet.
6. **Small UI debts**: clock hour hand snaps across 12 while dragging; calendar starts at today;
   path summaries are cut by character count.

## Roadmap

Order agreed on 6 Nov: login with email, stories, profile sync, small social, Android APK,
deploy for the field test. Stores and RevenueCat come after the first dry test; until then
`billing.field_test` stands in for payments.

### 1. Login with email (1 week)

- SMTP for GoTrue (magic-link mail) on the local stack and the server; Inbucket locally.
- Sign-in screen in Profil: email → "Link gesendet" → session; sign-out; account deletion and
  export from the app (API has both).
- Six-digit user tag on first sign-in: `users.tag`, unique, uppercase without 0/O/1/I; shown in
  Profil; usernames stay freely editable.
- Done when: a fresh install signs in on web and Android, the tag shows, re-opening keeps the
  session, consent re-prompt still works.

### 2. Stories (1 week)

- Generation screen: progress states (writing, annotating, notes), error texts, retry.
- Library: official stories cached offline; archive limits by tier; archive/unarchive.
- Quality loop: thumbs up/down per story stored with the `llm_usage` row; admin analytics shows
  rating next to cost.
- Review round like the other areas, then mark reviewed.

### 3. Profile sync (1 week)

- Round trip on two devices: words, variants, lists, sentences, events, settings, stories,
  lecture and story progress, activity. Conflict rule stays "events win, state is derived".
- Profile fields on the server: username, avatar, native and study language, streak summary and
  this week's minutes (aggregated server-side) so friends can read them.
- Done when: device B shows device A's lists and streak within one sync cycle, regrades replay
  correctly, deleting a list on A tombstones it on B.

### 4. Small social (1–2 weeks)

- Tables `friendships(user_a, user_b, status, requested_by, at)` and
  `shared_items(id, owner, kind, ref_id, visibility)`.
- API: find by tag, request, accept, decline, block; friends list with streak, supporter badge,
  current language, minutes this week; share a list or story; import a shared item.
- App: Freunde section in Profil, requests through the inbox, "Teilen" in the list and story menus.
- Privacy: aggregated activity only; blocking hides both ways; profile visibility respected.

### 5. Android APK (3 days)

- Signed debug/internal build from CI (keystore in secrets), `cap sync`, deep link for the
  magic link, packs on the filesystem plugin, Sentry client SDK.
- Device test: fresh install → onboarding → core pack on cellular → offline session → sign-in →
  sync → story generation.

### 6. Deploy for the field test (2 days)

Target and flow are in `infra.md`. Checklist:
1. Server env: `PIPER_URL`, `NLP_URL`, `DATABASE_URL`, JWT secret, service role key, CORS
   origins for `app.<domain>` and `admin.<domain>`, LLM key, SMTP, Sentry DSN.
2. Pull agent once, check `/health`; publish dictionary v4 and audio core v4 to the server's
   Supabase; `seed-lectures` for the admin.
3. First admin user with TOTP; `billing.field_test = true`; testers get their accounts by magic
   link.
4. Hand out `app.<domain>` (PWA) and the APK; collect feedback through the inbox or a form.

### Afterwards

RevenueCat SDK and store products, Stripe Checkout and Tax on web, supporter tip jar, App Store
and Play listings, second native language (English), second study language.
